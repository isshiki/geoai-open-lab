# 実験05：歩行規則とグラフ構築の仕様

2026-10-04。保存済みOverture Transportation 2026-09-23.1を対象とする。
これは道路属性の監査と次の実装仕様であり、徒歩経路が検証済みという意味ではない。
[主分析計画](station-access-aging-plan.md)のP0、100m接続上限、小成分保持、駅中点方式は変更しない。

## 公式仕様と実験上の選択

公式資料を2026-10-04に再確認した。

- [Roads](https://docs.overturemaps.org/guides/transportation/roads/): 明示的アクセス制限がない場合の許可は、classと地域の規則等に依存し、スキーマ自体が徒歩許可を保証しない。通行禁止遷移には単純なものと複数segment経由のものがある。
- [Scoping Rules and Travel Modes](https://docs.overturemaps.org/guides/transportation/scoping-and-travel-modes/): 条件はANDで評価し、複数の一致するアクセス規則は最後の一致を採用する。modeが指定されていないheading制限を自動車限定とは読まない。

したがって、通常の自動車一方通行は徒歩と無関係だろうという推測で、保存済みデータのmodeなし方向制限を捨てない。ただしデータの表現が現実の徒歩規則と一致する保証もない。この影響は駅接続・経路図・到達不能率で検証し、品質不足なら相関の解釈へ進まない。

## 実装済み：明示規則の監査

```powershell
uv run --no-sync python scripts/station_access_aging_walking_rules.py
```

追加通信なし。元の137,231 segmentを読み、between境界で区間を分けて、その内部の両方向を評価する。
`allowed` / `designated` は許可、`denied` は禁止。規則が決まらなければ `default_required`。
日時・目的・私的資格は推測せず、条件が一致する場合としない場合の両方を保持する。
後の確実な規則で決定できる場合を除き `conditional_unresolved` とする。
明らかに車両だけの条件は徒歩に不一致とする。未対応のmodeや条件は未確定に倒す。
この監査では道路classからの既定許可は入れず、時刻を選んで最も通行しやすい結果を出さない。

保存先はGit管理外 `data/cache/station_access_aging/walking-rules/audit.json`。
集計値、入力SHA-256、スクリプトSHA-256、release、実行UTC、Python版を保存する。
生レコード・識別子・座標は集計JSONに転記しない。

## 次に実装するグラフの規則

以下は相関を見る前の工学的設定。現地の法的通行可否を保証するものではない。

1. 分析ネットワークは元の道路集合に限定し、connector補完6件を加える。補助segment 1件は遷移照合用にとどめ、追加の未取得connector 2件を推測で生成しない。範囲外へ続く遷移を境界台帳に残す。
2. classの既定候補はresidential / service / unclassified / primary / secondary / tertiary / footway / pedestrian / steps / path / track。階段は含むがバリアフリーとは説明しない。motorway / trunk / cycleway / bridleway / unknownは明示的な徒歩許可がない限り候補にしない。明示規則の結果とclassによる仮定を別列に保存する。subclass・road_flagsの自動車専用等の指定がある場合は未監査のまま許可せず、次の実装時に全出現値を照合する。
3. 日時・目的・私的資格に依存して許可が変わる区間は未判定として主グラフに入れない。これは保守的な分析上の選択であり、常時通行禁止という意味ではない。未判定除外の件数・距離帯への影響を報告する。
4. connector位置とaccessのbetween境界で分割し、有向辺を作る。長さはEPSG:6677。atはWGS84測地距離による割合で位置を求める。分割境界を経緯度の平面補間で置かない。線の交差だけでは接続しない。内部の規則境界はそのsegment専用の仮想節点とする。
5. 同じconnectorでも異なる道路の平行辺を潰さない。禁止遷移は現在の節点だけでは判定できないため、進入segment・headingと禁止sequenceに必要な履歴を保持する。複数段階の禁止を最初の曲がり角だけの禁止へ置き換えない。人工的な区間分割を道路間遷移と数えない。
6. 主仕様の最寄り辺投影・100m接続・小成分保持を適用する。駅へ到達可能な成分に接続し直す処理は主仕様へ混ぜず、既存A12だけで行う。駅・メッシュの接続距離と道路距離を別々に保存する。
7. 未取得域を通る経路が必要な場合は境界未検証。追加取得なしで完全性を主張しない。外縁までの距離下限と取得域内の駅距離を比較し、範囲外の駅・道路が結論を変えないかを別途監査する。

実装順は、subclass/flags監査、区間分割・有向辺、遷移制限付きの小さな架空ネットワーク試験、実データの成分監査、駅・メッシュ接続、距離計算。
各段階で未判定条件・境界依存を数える。人口率・相関は距離の品質確認後とする。
この仕様によるグラフ構築、通過履歴を持つ探索、駅距離計算はまだ実装・実行していない。
