# 駅の縄張りランキング：引き継ぎ・移行計画

2026-10-04。**承認済み・ローカル移行検証済み**。テーマIDはstation-territory。POI記事の続きの「実験05/06」とはしない。配置・3者の協調は[共通計画](../../../docs/project-organization.md)に従う。

## 1. 目的と移行元

東京23区の駅の縄張りを、既存の歩行道路網から分析して個人ブログの記事にする。既存地図プロダクトへの機能追加はしない。

移行元はユーザー指定のeki-walk内 `artifacts/station-ranking-20261004/`。README、article_scope.json、definition-lock.json、docs全7本、主要集計・検証スクリプト、テスト7件の実装、Notebook、入力manifest、保存済み結果を確認した。コードの公開元[eki-walk](https://github.com/isshiki/eki-walk)・[rail-gap-map](https://github.com/isshiki/rail-gap-map)はGitHub APIでPublic・Apache-2.0と確認済み。会社資産は使用しない。

退避済みの旧高齢化調査の計画・集計コードも比較した。旧調査はOverture道路、2市、メッシュ中心、駅線中点、接続100mによる近似距離。本テーマはOSM道路、23区、25m格子、ホーム線接続、同名駅統合、人口面積按分であり、同じ距離指標ではない。旧コード・閾値を共通化のために復活させない。共通の人口ZIPだけは同一hashで再利用できる。

## 2. 採用する定義

| 項目 | 継承する規則 |
| --- | --- |
| 対象 | N03行政区域コード13101〜13123の和集合。EPSG:6677。駅代表点が境界を含む23区内ならランキング候補。範囲外駅も最寄りの競合に残す |
| 駅統合 | N02グループでまとめ、同名グループの代表点が600m以内なら連結。連鎖統合で端同士が600m超となり得る。異名駅は近くても統合しない。最終代表点は構成駅行の中点座標の平均、keyはN02グループコード集合 |
| 歩行距離 | ekiwalk固定4176263に基づく未丸めgrid-base。移行元仕様はホーム線から100m以内の道路節点接続（候補なしの場合は上限なし最近傍接続。原コード確認による説明補足）、道路点間隔20m以下、25m格子、近傍8道路点、道路から300m以内。原コード・設定・入力から再現時に照合する。実入口や障害物横断可能性を保証しない |
| 面積 | 有効格子中心が23区内の格子数×25m×25m。人口ありメッシュ内の厳密交差面積を併記。境界交差による全面積も補助列とし、中心方式との差を明示 |
| 人口 | T001142総人口をメッシュ全体の面積に対する「メッシュ∩23区∩格子」の比で按分。駅へ割当できる部分だけで再正規化しない |
| 人口加重平均距離 | 按分人口×未丸め距離の合計÷割当人口。推計人口1,000人以上。実際の通勤・駅利用距離ではない |
| POI | 既存OSM PBFからshop/amenity/tourism/leisure/healthcare/officeを使う移行元の分類。設備等の除外と優先分類はpoi_policy.jsonを継承。OSM要素typeとidで一意化。施設の実数とは呼ばない |
| 未割当 | 道路から遠い・経路が成立しない領域、人口、POIを別に残す。無条件の最近傍補完をしない。人口未掲載・0・欠測を区別 |
| 境界 | 23区外駅はランキングから除くが割当量を保持。区境で切れた区内駅は主表に残しフラグ表示。計算bboxの保守的な危険フラグの駅は除外。両者を混同しない |
| 順位 | 丸め前の値で降順。同値は同順位、表示順のみkey昇順。本文は各10駅、10位同値は補足に全件。人口下限を結果に合わせて変更しない |

人口ありメッシュ面積を住宅用地・可住地面積と呼ばない。250m内の公園等が残る。人口内訳の一様性は推計仮定である。表示用の穴埋め・平滑化・飛び地吸収をランキング集計へ入れない。15分制限は最寄り駅距離の打切りには使わない。

記事の主指標は面積（人口あり面積併記）・推計人口・POI登録数（業種別含む）・人口加重平均距離の4種類。高齢化率と非人口加重平均距離は採用しない。旧図表・監査データは移行元へ残し、公開Notebookの表示・主要表の列にも混入させない。

## 4. 今回の読み取り検証と残る問題

今回、移行元スクリプトを実行せず、別の読み取り計算で以下を照合した。移行元を書き換える再生成コマンド・pytestは走らせていない。

- 集計スクリプト11本のhashがexecution-manifestと一致。
- 保存済み格子のowner別件数から面積を再集計して一致。
- 人口の元CSVと保存済み交差重みから全駅をgroupbyで再集計して一致。重みを作る幾何処理の独立検証ではない。
- OSM要素IDの重複なし、保存済みPOIから駅別・業種別の再集計が一致。
- 採用5列（面積の補助指標を含む）の上位10件を別ソートで再確認して一致。これを道路網や入力の完全性の証明とはしない。
- 人口加重平均の分子/分母と保存値の整合を確認。人口距離積の分子自体は未再計算。
- Notebook10セル・コード4セルは出力・実行番号・添付なし。

## 5. 実装範囲と再現性の段階

承認後、`projects/station-territory/` 内に限定して分析用の小さなパッケージを作る。最初の構成は `src/station_territory/` のterritory.py（駅・格子・順位）、population.py（人口按分）、poi.py（分類・割当）、必要な入出力/検証・図表コード。ファイル数を先に増やさず責務が分かれる範囲だけ切り出す。既存eki_walk.pipeline全体やWeb製品への依存は持ち込まない。駅統合等を移植するときは元のライセンス・出典・commit・変更点を残す。

1. **入力の固定**：既存データを読み取り、必要なファイルだけproject/dataへhash付きで取り込む。取得データ・中間格子・検証用の旧結果を別ディレクトリにし、旧結果は新しい計算の入力にしない。元プロジェクトは編集しない。
2. **格子以降の再実行**：駅対応・境界・人口按分・POI集計・順位・図表を再生成。Notebook `notebooks/01_rankings.ipynb` は入力確認→4種ランキング→検証→限界の順にする。ここで再現できる範囲を明示する。
3. **道路から格子までの再現**：公開rail-gap-map固定版と設定で格子が作れる手順を用意し、既存入力から再生成して比較する。道路網・最短路・水面・接続・範囲の扱いを固定し、サイト機能や住所検索用データを不要に取得しない。これが未検証なら「原データから全工程再現済み」としない。
4. **差分判定**：旧結果と不一致なら先に原因を記録。幾何・統合・欠測の規則を変える必要がある場合は、変更前後・影響する駅/順位を示して相談する。既存順位に合わせて調整しない。

Python・DuckDB等には移行元とラボで版の差があるため、専用pyproject/uv.lockで依存を固定し、POI環境を変えない。DuckDB spatial拡張も必要な版がローカルにあるか先に確認し、自動INSTALLしない。集計結果はテスト期待値に丸写しせず、人工例と保存則で検証する。

必須テストは同名600mの境界・連鎖・異名・安定key、区境とbbox除外の違い、メッシュ部分交差と未割当の保存、人口0/欠測と1,000人境界、重み付き距離、同順位、POI優先分類・重複ID・不完全relation、cache不一致。既存7テストは読んだが新環境での再実行はこれから。POI側のテストも、配置変更後に全件実行する。
