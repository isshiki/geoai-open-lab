# 東京都の駅中心1km四方：将来の比較計画

計画のみ。東京都全体のPOI取得・一括集計・類似度計算は未実施。今回の実測は吉祥寺1駅に限定する。

東京都内の駅を同じ条件で一括集計する作業は、類似地域検索の実装工程として扱う。独立記事にするだけの発見が出るまでは、別の記事テーマとして増やさない。次回記事『「吉祥寺」に似た街はどこ？　POIデータで東京都内の駅周辺を比べてみた』へつなげる。記事順序は[ロードマップ](roadmap.md)を参照。

## 対象と地域単位

EPSG:6677は、JGD2011 / 平面直角座標系第IX系を表す識別番号。東京都周辺の位置をメートル単位で扱い、1km四方や250m格子を計算するために使用する。

- 対象は東京都内に代表点がある旅客鉄道・軌道の駅。23区だけでなく吉祥寺を含む多摩地域も含める。行政界データの版・利用条件を取得前に固定する。境界上の代表点は東京都ポリゴンがcoversするものを採用し、監査する。
- 駅データは公式N02の固定版。同名だけで統合せず、N02_005gで複数路線をまとめる。同一グループのN02_005cがグループコードに一致する駅線を代表とし、EPSG:6677の長さの中点を使う。複数線は結合、非連結は最長線・同長はWKT順で選び記録する。代表がない場合は停止し個別確認。将来実行前に全駅の例外監査と採否規則を確定し、結果を見て変更しない。
- EPSG:6677の代表点±500m、1km四方。南西角を地域固有の格子原点にして250m16区画・500m4区画。北を上とし部分区画を作らない。
- 駅ごとのAOIが重なる場合、同じPOIが複数駅の地域特徴量に入ることを許容する。駅の縄張りの排他的な所属や商圏分割ではない。

## 取得と保存

1. N02と都境界の版、対象駅の統合規則、AOI一覧を固定し、重複駅・代表点・都境界を検証する。
2. 全対象駅のAOIを完全に覆う検索範囲の和集合を作る。都境界外に伸びる駅周辺AOIも取得範囲に含める。
3. 固定releaseのOverture Placesを一つの取得処理として全範囲から取得し、IDで重複を除く。駅ごとに同じデータを再ダウンロードしない。LIMIT・サンプリングなし。必要属性とsources/licenseを保持する。
4. 全範囲の取得完了を検証してから各駅の正方形へ投影座標で割り当てる。未取得範囲を0件としない。
5. release・schema・駅版・都境界版・取得日・範囲・件数・SHA-256をmanifestに記録する。取得済みスナップショットはGit管理外dataで保存し、公開最新版へ自動追従しない。

[Release Calendar](https://docs.overturemaps.org/release-calendar/)の公開保持は最大60日（2回の月次release）。同じreleaseが入手不能なら停止して報告し、別releaseへの変更は再承認を受ける。現在の2026-09-23.0を将来も取得できるとは約束しない。

## 特徴量と比較

固定15列を共通定義で生成し、1地域1行へ結合する。東京都全駅の「その他」比率を確認し、必要なら表示カテゴリを追加する。追加時はschema versionと対応表を更新し、吉祥寺を含む全駅を同じ定義で再計算する。都合のよい結果を得るための地域別カテゴリ変更はしない。

密度・カテゴリ構成比・集中度が候補。登録数と密度を重複投入しない（1km²では数値が同じ）。構成比の総和制約、カテゴリ欠損、POIの収録差、最大密度の外れ値感度を確認し、正規化・特徴量選択・距離関数は全駅の分布を確認後に決定する。今回それらを最終決定しない。

## 公開物と条件

コード、集計済み特徴量、図、manifest、出典を公開候補とし、個別POIと駅線等の生データを公開Gitへ入れない。Notebookは出力を消す。集計済みCSV等も自動でforce-addせず、対象成果物を指定してデータポリシーに沿って公開可否を確認する。
