# Qiita続編企画：POIから街を数値化する実験のまとめ

作成日：2026-10-19。前回のQiita記事[『POIオープンデータ入門：Foursquare・Overture・OpenStreetMapの違いと選び方』](https://qiita.com/isshiki/items/4a50f54cc8e5cd649f03)の続編候補。公開は未決定で、この記事企画を記録しただけである。

## 判断

続編を1本出す価値がある。前回は「どのPOIデータを選ぶか」を整理した。今回は、選んだOverture Maps Placesを使って、街を数値化し、似た街を探し、分類し、Embeddingへ変換した結果と限界をまとめる。個別記事5本の短縮版ではなく、一連の実験で判断がどう変わったかを主題にする。

## 推奨タイトル

**POIで街を数値化して分かったこと：類似検索・クラスタリング・Embeddingと分析範囲の影響**

「Python」を強める場合の候補：

**Pythonで街を数値化する：POIの地域特徴量・類似検索・クラスタリング・Embedding**

## この記事で答える問い

1. POIから「1地域＝1行」の特徴量をどう作るか。
2. 手作り特徴量、細分類、Embeddingで似た街の順位はどう変わるか。
3. クラスタリングで何が見え、何を街の種類と断定できないか。
4. 駅中心500mを800mへ広げると、結果はどの程度変わるか。
5. この方法をどんな限定された用途なら使いやすいか。

## 推奨構成

1. 前回記事からの接続：POIデータを選んだ後、街の比較へ進んだ。
2. 地域特徴量：吉祥寺駅周辺を1行15列へ変換した。
3. 類似検索：656駅を同条件で比較し、密度だけとは違う順位になった。
4. クラスタリング：基準駅を置かず3群へ分けたが、AOI重複の抑制に敏感だった。
5. 地域Embedding：961カテゴリを64次元へ圧縮したが、安定性改善は確認できなかった。
6. AOI感度：500mから800mへ変えると、3方式とも上位候補が変わった。
7. 結論：結果は街の絶対的な性格ではなく、データ・特徴・範囲を固定した一側面である。
8. 使いどころ：駅から5分で行けるカフェなど、問いと範囲を先に限定する。

## 図とコード

- 冒頭：地域特徴量→類似検索→クラスタリング→Embedding→AOI感度の流れを1枚にまとめた新しい概念図。
- 結果：既存記事の図から各段階1枚以内を再利用する。
- コード：データ取得の全手順を再掲せず、地域特徴量の集計、標準化と距離、TF-IDF→SVDの核心を3断片程度に絞る。
- 再現手順：各Notebookと検証文書へリンクする。

## 書かないこと

- Embeddingで類似検索が改善した、とは書かない。
- 3クラスタが自然に存在する街の種類だとは書かない。
- 500mまたは800mが正しい範囲だとは書かない。
- 類似順位を住みやすさ、街の優劣、実際の人出の順位として扱わない。
- MAUP、EPSG、Embedding一般論をこの記事だけで詳説しない。必要最小限に説明し、独立記事へ分ける。
