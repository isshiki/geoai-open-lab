## 用語とEPSG

- 楕円体：地球の形を計算しやすく近似する形。地形の起伏をそのまま表さない。
- 測地基準系：位置を測る基準。楕円体の形だけでなく、地球にどう位置づけるかも関係する。
- 地理座標系：緯度・経度という角度で位置を表す仕組み。
- 地図投影法：地球の曲面を平面へ写す方法。平面へ写す以上、何らかのひずみが生じる。
- 投影座標系：基準系、投影法、原点、軸、単位などを組み合わせた平面上の位置の表し方。
- EPSGコード：座標参照系などの定義を識別する番号。「投影法番号」でも「精度の順位」でもない。
- 測地線距離：楕円体の表面で2点を結ぶ最短経路の距離。道路距離や実際の徒歩距離ではない。
- 等積図法：面積の比率を保つ図法。距離・角度・形がすべて正確という意味ではない。

正式名称・軸・単位・適用域は[方法のEPSG表](crs.md#epsgと軸の確認)を転記する。4326=WGS 84、6668=JGD2011は地理座標系（degree）。3857=WGS 84 / Pseudo-Mercator、6677=JGD2011 / Japan Plane Rectangular CS IX、8857=WGS 84 / Equal Earth Greenwichは投影座標系（metre）。東京都の固定分析に6677を使うが、日本全国や世界の汎用座標系とは書かない。JGD2011を日本の最新基準と呼ばない。

## 記事掲載コード

既存環境での実行は[方法](crs.md)。最小例は以下。

```python
from pyproj import Transformer, Geod

lon, lat = 139.57980985190306, 35.70314448120142
to_local = Transformer.from_crs(4326, 6677, always_xy=True)
x, y = to_local.transform(lon, lat)  # 経度・緯度 → 東・北 [m]
back = Transformer.from_crs(6677, 4326, always_xy=True)
print(back.transform(x, y))

geod = Geod(ellps="WGS84")
lon2, lat2, _ = geod.fwd(lon, lat, 90, 500)
print(geod.inv(lon, lat, lon2, lat2)[2])
```

```python
import geopandas as gpd
from shapely.geometry import Point

point = gpd.GeoSeries([Point(lon, lat)])
point = point.set_crs(4326)  # 元座標の意味を指定。数値は不変
point_m = point.to_crs(6677)  # 座標を変換
circle = point_m.iloc[0].buffer(500, quad_segs=512)
# poisはWGS84の経度・緯度が正しく設定されたGeoDataFrame
# withinは境界を含まないので、今回と合わせるならcovered_by
selected = pois.to_crs(6677).loc[lambda g: g.geometry.covered_by(circle)]
```

## 使い分けと限界

WebメルカトルはWebタイルの表示・配信に適している。座標の単位がmだからといって、そのまま距離・面積・密度を地上値として使わない。距離は測地線または対象地域に適した投影で検証し、広域の面積は測地面積や等積図法を選ぶ。
東京の固定入力では6677が妥当だったが、日本全国・島嶼・世界にそのまま拡張しない。縮尺誤差、基準系変換精度、POI元位置の精度を区別する。面積を保つ図法でも見た目の形や方向・距離は変わる。
登録数は実店舗数でも営業中店舗数でもない。密度だけから需要・売上・住みやすさを判断しない。合成密度例を実際の都市ランキングに見せない。世界境界は粗く、de factoの表現を含み、国境の法的主張や公式国土面積には使わない。
