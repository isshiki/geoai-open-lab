# 記事引き継ぎ：吉祥寺の高一致は一般的か

Notebook 11の独立した補足検証です。既存の記事用結果・図は変更していません。記事は未執筆・未公開です。

## 主な発見

**吉祥寺の1km四方と道路800mのJaccard 0.940357は、全駅の典型値ではありません。** 全656駅の中央値は0.782818、P10–P90は0.611780–0.904961。吉祥寺は96.57百分位です。全体では0.9以上79駅、0.7未満151駅でした。

ただし「どの駅も大きく違う」とは書けません。高一致の駅もあり、カテゴリ構成差は集合差より小さい場合がありました。全駅の四方対道路800mの構成差TVD中央値は0.019838です。TVDは既存6群＋その他＋欠損の構成比差の絶対値合計÷2で、0が同じ構成、1が重ならない構成です。粗いカテゴリのため細分類の違いは隠れる可能性があります。

### 距離と定義を分ける

| 比較 | 確認すること | 全656駅のJ中央値 |
| --- | --- | --- |
| 直線400mと500m | 同方法内の上限変更 | 0.758140 |
| 直線400mと800m | 同方法内の上限変更 | 0.354978 |
| 直線500mと800m | 同方法内の上限変更 | 0.476678 |
| 道路400mと500m | 同方法内の上限変更 | 0.731554 |
| 道路400mと800m | 同方法内の上限変更 | 0.351668 |
| 道路500mと800m | 同方法内の上限変更 | 0.478550 |
| 直線500mと道路500m | 同じ名目距離での定義変更 | 0.666667 |
| 1km四方と道路800m | Notebook 11との連続性。距離と形も異なる | 0.782818 |

上限を広げる比較は集合が包含関係になり、Jaccardは小さい集合の件数÷大きい集合の件数になります。低下自体を誤差や分析の失敗とは解釈しません。このモデルでは道路500mは直線500mにも含まれるため、この比較も件数比と同じ値です。四方対道路800mは包含関係とは限りません。

同じ名目500mでも、歩行道路・接続の定義を入れると採用POIが変わります。道路側が正確な実歩行経路という意味ではありません。

## 全駅集計と図の母集団を区別

- 有効656駅、駅接続上限100m超過0駅。駅接続距離中央値5.867m、最大48.147m。
- 記事用図の分布・中央値は、事前に固定した「比較集合の和集合30件以上」を主表示。
- 四方対道路800mは646駅、J中央値0.782395、P10–P90 0.614518–0.904050、0.9以上76駅、0.7未満147駅。
- 同500mの定義比較は642駅、J中央値0.668751。
- 四方対道路800mの低件数10駅は別表に保存。30件未満だから除外して消すのではなく、全駅値も併記。
- 図の0.782 / 0.669と、全656駅の0.783 / 0.667を混ぜない。

## 代表例の使い方

対照8駅は結果を見る前に固定しました。全件を[検証記録](walking-sensitivity-validation.md)へ掲載しています。四方対道路800mの例は、吉祥寺0.940、新宿0.752、東京0.804、立川0.921、町田0.948、北千住0.920、高尾0.847、奥多摩0.981です。

規則選択の最小・最大（和集合30件以上、同率はID順）は昭和島0.016949、高尾山口0.987805です。昭和島は四方59件、道路800m 1件、共通1件。高尾山口は四方82件、道路800m 81件、共通81件です。和集合が30件以上でも、一方の件数が非常に少ない例はあります。最小例だけを一般例として強調しないでください。

地図で言えるのはPOIの位置と採用集合の違いです。「川があるから」「線路で分断されるから」「OSMが欠落したから」といった原因は未確認です。道路までの接続が成功しても、実際の出口や通行可能性が保証されるわけではありません。

## 掲載コード

固定入力からの全駅計算はCLIで行い、読者向けには次の短いコードで検証済み表と図を確認できます。取得処理はありません。

```python
from geoai_open_lab.walking_sensitivity import load_results, OUT
from IPython.display import display, SVG

audit, conditions, pairs, distributions = load_results()
display(distributions[distributions.cohort.eq('all')][
    ['first', 'second', 'jaccard_median', 'jaccard_p10', 'jaccard_p90']
])
display(pairs[pairs.region_id.eq('n02-003584')])
display(SVG(filename=str(OUT / 'distributions.svg')))
```

`load_results()`は出力ハッシュを照合します。全駅の再計算は[検証記録のコマンド](walking-sensitivity-validation.md#再現コマンドと成果物)を参照。

## 言えること・言えないこと

- 対象は保存済み定義の東京都内656駅グループ。全国やすべての駅定義へ一般化しない。
- 分析範囲の定義によるPOI集合・カテゴリ構成の感度を確認した。徒歩圏や商圏の唯一の正解は求めていない。
- 古典的MAUPの固定外枠に対するゾーニング効果を分離していない。高一致でもMAUPの反証ではない。
- UGCoPは地理的文脈と実際の活動・曝露の場所や時間の不確実性に関係する。今回の静的POI比較はその空間的範囲選択に関連する検証で、UGCoP全体や因果関係を実証したわけではない。
- 駅代表点は出口・改札ではない。接続線は実通路を確認していない。80m/分は仮定で、待ち時間・坂・階段負荷・混雑は含まない。
- POI登録数は営業中店舗数・売上・需要・住みやすさではない。欠落と時点差があり、8群の構成にはその他・欠損も含む。
- 重複する駅周辺を656の独立標本と見なした検定はしていない。
