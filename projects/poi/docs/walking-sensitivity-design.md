# 駅周辺の範囲定義：656駅の補足検証

2026-10-22、結果を計算する前に次を固定した。Notebook 11 / commit `3af4afe` とその生成結果は変更しない。新規取得・学習は行わない。

## 事前仕様

- 既存656駅グループ・代表点・EPSG:6677を維持。正方形±500m、直線400/500/800m、道路400/500/800mの7条件。
- 道路は固定 Geofabrik 関東 `kanto-261001`、既存 eki-walk 抽出網。入口ではない駅代表点とPOIを最近傍辺へ投影し、双方の接続距離を道路距離に加える。接続上限100m。5分=400m、10分=800mは80m/分の仮定。
- 同方法内の3距離の全3対ずつ、直線500m対道路500m、正方形対道路800mの8比較。方向は小→大、直線→道路、正方形→道路。
- POIは同じ保存済み release `2026-09-23.0` と800m用保存済み補完48件。東京都境で切らない。全駅の取得範囲をmanifestから確認する。
- 代表点から道路へ100m以内に接続できない駅は道路比較から除外し、幾何学的比較には残す。被覆不足は0件にせず停止。POI接続不可は徒歩圏から除外し理由を記録。
- 比較する2集合の和集合30件未満を「低POI数」として別集計する（事前の監査上の閾値）。全有効駅の値も併記。和集合0件のJaccardは未定義、いずれか0件なら構成差も未定義。
- 構成は既存6群+その他+欠損、分母は各条件の全登録数。構成差は各群の差（第2条件−第1条件、ポイント）とTVD=構成比の絶対差合計÷2。件数差も第2−第1。駅を等重みで集計。
- 分位点は線形補間。吉祥寺の位置は同じ集計対象の経験百分位（同値の半数を下側に含む）。近接・重複AOIがあるため独立標本と見なした有意差検定はしない。

## 結果を見る前に固定した対照駅

吉祥寺 `n02-003584`、新宿 `n02-003700`、東京 `n02-003766`、立川 `n02-003634`、町田 `n02-004387`、北千住 `n02-003260`、高尾 `n02-004029`、奥多摩 `n02-003069`。東京は既存グループのうち上記IDに固定し、同名別グループを結果を見て選ばない。大規模な駅・都心・多摩の駅を含む対照であり、統計的な代表標本ではない。

結果から選ぶ図の高一致・低一致例は、正方形対道路800mの有効かつ和集合30件以上の駅をJaccardでソートし、最小・最大の各1駅。同率はregion_id昇順。全駅表・全対照駅も残し、例だけを結論に使わない。

## 計算と監査

全道路を一度読み込み、各駅±900mに接する辺を元の長さのまま抽出する。候補POIは±800m内。800m以内の経路と100m以内の最近傍接続は抽出範囲内に収まる。交差するだけの辺をつながない。長い辺も抽出から落とさない。

固定道路の長さ0の3辺は端点を同じノードへ縮約して接続を保持し、投影対象から除く。局所網の同距離投影はノードID順で決定する。Notebook 11の吉祥寺では該当しない。重複辺の長さは最小を保持する。

吉祥寺について既存11の4条件のPOI ID集合・件数・道路距離・接続距離と照合する。候補の広さが違っても採用集合は一致すること。結果再実行、境界、包含、空集合、低件数、構成差、入力ハッシュを検査する。
